# CLAUDE.md (admin)

Admin panel for gallery.sksat.net. This is a separate Qwik/QwikCity project under `admin/` with its own `package.json`, `node_modules`, and Cloudflare Pages deployment. Read alongside the root [CLAUDE.md](../CLAUDE.md) — workflow rules, fixture conventions, and VRT baseline policy are inherited from there. Code shared with the public gallery lives in `../shared/` (`@shared/*`, plain TS; see the root CLAUDE.md): e.g. `shared/overlay/` gives the edit page's full-screen preview (`src/components/photo-preview.tsx`) the same look and progressive loading as the gallery's photo overlay.

## Differences from the root project

- **Dev port**: `5175` (root uses `5174` for Playwright). Avoids conflicts when both projects' dev servers are running.
- **Routing**: `/` dashboard, `/media/` + `/media/[id]/` (photo metadata), `/tag/` (tags), `/setting/` (site settings), `/camera/` + `/camera/new/` + `/camera/[id]/` (camera records; route paths are singular, except the mass noun `/media/`). E2E/VRT data comes from `e2e/fixture.sql`. Links from the list to an edit page carry the list URL in `?back=` (`mediaEditHref` / `safeBackHref` in `src/lib/format.ts`); the edit page's "← Media" returns there and its ‹ 前へ / 次へ › step through that list (`src/lib/neighbors.ts`). Its unsaved-changes guard uses `usePreventNavigate$`, which is experimental and enabled in `vite.config.ts`. A tap on the edit page's photo opens a full-screen viewer (`src/components/photo-preview.tsx`, `?fs=1` while open) for going through a batch: ←/→ or a swipe step through the same list as 前へ/次へ (←/→ also on the page when no field has focus), and 1/2/3 or its buttons only mark the photo's new visibility as pending (`src/lib/review-pending.ts`, kept in `sessionStorage` per list) and go on to the next photo; a bar (in the viewer above the buttons on phones, top right from `sm`; on the page while it is closed) counts them by level and applies them all at once with 反映 (`useApplyPending`, the bulk update in chunks of 100; photos that become public or unlisted are shown as thumbnails first) or drops them with 破棄, and 元に戻す reverts the whole batch (`useUndoPending`). Pending choices trigger the leave guard except when stepping to another photo. Key handling is in `src/lib/review-keys.ts` (no shortcuts while typing, composing or with modifiers; 1/2/3 not on key repeat). 反映 waits while the form has unsaved edits. "← Media" adds `#m-<id>`, and the list scrolls that photo into view. On phones the `/media` filter form sits in a `<dialog>` opened with `showModal()` as a bottom sheet (a `<noscript>` style shows it inline without JS), and its selects apply as soon as they change; from `sm` up the same dialog is styled inline and the Filter button applies (a closed select fires `change` on every arrow-key step). Filters on `/media` apply in place (client-side navigation), so any `<Link>` there whose href depends on the query is keyed by its href: Qwik City's `Link` keeps the href it was first rendered with while the route stays the same.
- **Cameras**: table names are singular (`camera`, `camera_image`; `media` is a mass noun). A photo links to at most one `camera` row via `media.camera_id` (migration `0002_camera.sql`, which replaced the old free-text `camera_make`/`camera_model` columns). The camera row is the single source of truth: it has `manufacturer` / `manufacturer_url` (kept on the camera for now; a `manufacturer` table once several cameras share one) and `model`. Cameras have no delete yet; the FK has no `ON DELETE`, so a camera with photos cannot be removed by SQL either. Pictures of a camera live in `camera_image` (`ON DELETE CASCADE`, ordered by `position`, unique per camera + file); `file` is a bucket path validated by `validateImageFile`; on the camera page a bare file name means `/camera/<slug>/<name>` (`resolveCameraImagePath`). Camera pictures have no upload (photo uploads cannot target `/camera`), so the file is placed in B2 by hand. Removing a picture can be undone from the toast (`restoreCameraImage` puts it back at its old index in one D1 batch). The length limit of a bare name counts the prefix (`cameraImagePathLengthError`, checked in the browser and by the action).
- **Visibility and public ids** (migration `0003_visibility.sql`): `media.visibility` is `private` (default for new rows; admin only), `unlisted` (opens by URL, never listed) or `public`. `media.public_id` is the photo's id in public URLs (`/photo/<public_id>/`): 10 symbols from `23456789abcdefghjkmnpqrstuvwxyz`, set once at creation and never changed (triggers fill it in when an INSERT leaves it out and reject any change; a migration that rebuilds `media` must recreate them). App code generates it with `generatePublicId()` (`src/lib/public-id.ts`, `crypto.getRandomValues`); the trigger's `random()` is only a fallback for raw SQL. Visibility is set on the edit page or in bulk from `/media` (tick rows → Apply; at most one page, 100 ids; on phones a selection bar fixed at the bottom). The bulk action returns each changed row's previous visibility, and the toast's 「元に戻す」 sends it back through `useRestoreVisibility`. The API lists only `public` rows.
- **Upload status and folders** (migration `0004_upload.sql`): `media.status` is `uploading` (row created to reserve the path; the file may not be in the bucket yet) or `ready` (default, so existing and hand-inserted rows are ready). Only `ready` rows are photos: the admin's lists, Files view, prev/next and camera counts, and every API Worker query filter on it. `media.size` / `sha256` (unique, NULL for old rows) / `uploaded_at` are filled by uploads. Folders are implicit (built from `media.file`, `src/lib/folders.ts`) plus rows in `folder` (`path` like `/VRChat/2026-11`, unique) so that a folder created in the Files view exists while empty; empty folders are shown only when no filter is set. Folder names: 1–64 of `[A-Za-z0-9._-]` (trimmed, not starting with `.`), at most 8 deep and 200 chars (`validateFolderName` / `validateFolderPath`); the same characters as bucket paths, which go into URLs unescaped. Renaming and deleting folders are not supported.
- **Display path and trash** (migration `0005_path_trash.sql`): `media.file` is the B2 object key and never changes (the image Worker, the API Worker, thumbnails, og and uploads use it); `media.path` is where the admin shows the photo (folder + name; `path = file` until it is moved or renamed, a trigger fills it for inserts that leave it out). The Files tree, breadcrumbs, counts, search, list view and prev/next use `path`; the edit page shows the B2 key too when they differ. `media.trashed_at` marks the trash: trashed photos are left out of every admin list and every API Worker query (like private ones), and keep their `path` (unique only among photos not in the trash) for restoring. `LIVE_PHOTO` (`src/lib/types.ts`) is the admin's "listed photo" condition. The same migration renames `media.world` to `media.platform` (Real / VRChat; UI label "Platform"), keeping "world" for the VRChat world itself later, and drops `media.legacy_index`.
- **Public metadata and tags** (also 0005): how much of each photo's metadata the public site shows, per field and level (`src/lib/metadata.ts`, a copy of the API Worker's `workers/api/src/metadata.ts`, which applies them; a test there checks they match): ファイル名 (フォルダとファイル名 / ファイル名だけ / 出さない), 撮影日時 (秒まで … 年だけ / 出さない), カメラ (機種まで / メーカーだけ / 出さない), タグ (公開タグ / 出さない); location (no control yet; hidden by default, from `media.latitude` / `longitude` / `location_source` exif or manual, also 0005, nothing filled in yet), world (`media.world_id` wrld_… / `world_name`; `world_author_id` admin only) and exif (`media.exif`, a normalized JSON object) likewise have no controls or data yet; `media.metadata_read_at` (NULL until the original's metadata has been read) is admin only too. `/setting/` sets the site defaults (`setting` row `metadata_visibility`; file names hidden, the rest as before); the edit page's 公開する情報 overrides them per photo (`media.metadata_visibility`, a JSON object; the first option, 既定（…）, follows the site). Tags are published one by one: `/tag/` lists every tag with its photo count and a 公開 switch (undo from the toast); a tag first used on a photo gets a private `tag` row and the toast says so; the edit page marks each tag 公開 / 非公開 (`src/lib/db-meta.ts`).
- **Uploads** (Files view → Upload, Upload folder, or drop files/folders on the view; a folder's subfolders are created under the open one, hidden files are left out, `src/lib/drop-entries.ts` walks dropped folders; Upload folder is hidden on iOS, which cannot pick folders): the browser sends originals straight to B2; the admin only signs. Per file (`src/lib/upload-queue.ts`, pure, injected deps; `src/lib/upload-client.ts` for the browser side): bucket path = open folder + safe file name (`uploadTarget`, PNG/JPEG only, up to 100 MB), SHA-256 with `crypto.subtle`, taken-at from the VRChat file name or EXIF (`src/lib/taken-at.ts`, JST when no offset), then `POST /api/upload` (reserves an `uploading`, private row, numbering the name `a-1.jpg`… when another photo has the path; resumes the row with the same hash; answers `exists` for a hash that is already uploaded; returns the path and a presigned PUT signed over `content-type` and `x-amz-meta-sha256`, `src/lib/sigv4.ts` / `src/lib/b2.ts`), XHR PUT with progress (2–3 at a time, 3 tries with backoff, each with a fresh init), then `POST /api/upload/<id>` marks it ready only if the bucket has the object with the row's size and `x-amz-meta-sha256`. The upload key is B2 "Write Only" (no read, no HEAD), so that check goes through the image Worker's `AdminImage.stat` (its read key; `src/lib/object-stat.ts`); E2E binds `E2E_FAKE_B2_STAT_URL` (loopback only) to the fake bucket instead. The image Worker with `stat` must be deployed before uploads are enabled. Uploads that never completed are listed in their folder; each page view checks each of them again on its own (the completion, 2 at a time), so a file whose PUT went through becomes a photo without uploading it again. Only the ones that still fail stay, with the reason, 「アップロードし直す」 (the same file resumes the row) and 「削除」 (`useDeleteIncomplete`). In the panel, retrying a file whose PUT succeeded only repeats the completion, and 「閉じる」 drops failed rows too (they then show as incomplete). Settings: `B2_ENDPOINT` / `B2_BUCKET` / `B2_REGION` vars and the production secrets `B2_UPLOAD_KEY_ID` / `B2_UPLOAD_APPLICATION_KEY` (`getUploadConfig`; without them the Upload button is hidden). The bucket needs a CORS rule for the S3 API: origin `https://admin.gallery.sksat.net`, operation `s3_put`, allowed headers `content-type` and `x-amz-meta-sha256`, exposed `ETag` (the web UI's presets cannot express it; set it with `b2_update_bucket`). E2E points uploads at `e2e/fake-b2.mjs` (PORT+2), which checks the signature and hash with the test key.
- **Auth**: Production is behind Cloudflare Access, and every SSR/API request (static assets under `/build/*` etc. are served without it) is additionally checked by `src/routes/plugin@access.ts` (verifies the `Cf-Access-Jwt-Assertion` JWT against `ACCESS_TEAM_DOMAIN` / `ACCESS_AUD` in `wrangler.jsonc`; fails closed). This matters because the production `*.pages.dev` hostname is not covered by Access. The check is skipped only under `pnpm dev` (Vite) and when `ACCESS_DISABLED=1` is bound on a loopback hostname (`.dev.vars` for `pnpm serve`, `e2e/start-test-server.sh` for E2E). If you add an Access application, append its AUD tag to `ACCESS_AUD`.
- **Bindings**: D1 `DB` (metadata source of truth, see [migrations/](migrations/)). Bindings come from `wrangler.jsonc` only (Pages ignores dashboard bindings because `pages_build_output_dir` is set): top-level = production + local, `env.preview` = previews with **no D1** and only the preview Access AUD. Previews also get no B2 upload settings. Tests run against a real local D1 (sequenced via `e2e/start-test-server.sh` so wrangler dev opens the file _after_ seeding).
- **Thumbnails**: every thumbnail and preview (public or not, and camera pictures) is `/thumb/<preset>/<file>` (`src/routes/thumb/`), which calls the image Worker's `AdminImage` RPC entrypoint through the `IMAGES` service binding (`wrangler.jsonc`, production only: previews run unreviewed code, so they get neither D1 nor this binding and show placeholders), passing on the request's `Cf-Access-Jwt-Assertion`; the Worker verifies that JWT itself, so both the binding and a valid Access token are required. Responses are `Cache-Control: private`. `src/lib/images.ts` mirrors the Worker's preset list — only those presets exist, and each distinct file+preset counts toward the monthly transform quota, so do not add presets here. With `THUMBNAILS` empty (E2E sets `--binding THUMBNAILS=`) or no binding, `Thumb` renders a deterministic placeholder; the originals (up to ~37MB) are never loaded.
- **Dashboard usage cards**: 容量 adds up `media.size` of ready photos by visibility and top-level folder in one GROUP BY (`src/lib/storage.ts`; uploading rows shown apart, camera pictures not counted), with a monthly B2 cost estimate from the named price constants. Sizes there are base 1000 (`formatDecimalBytes`; the uploader's `formatBytes` is base 1024). The D1 card shows the database size from that query's `meta.size_after` and, when the optional production secret `CF_ANALYTICS_API_TOKEN` (account API token, Account Analytics: Read only) is set, today's (UTC) rows read/written from the GraphQL Analytics API (`src/lib/d1-usage.ts`, account/database ids in the `CF_ACCOUNT_ID` / `D1_DATABASE_ID` vars, cached 5 min with the Cache API), all against the Free plan limits. Without the token, or on an API error, the card says so and the page still renders. アクセス reads Cloudflare Web Analytics with the same token (`src/lib/web-analytics.ts`; `rumPageloadEventsAdaptiveGroups` filtered by the `WEB_ANALYTICS_SITE_TAG` var **and** `WEB_ANALYTICS_HOST`, since the site tag covers the whole sksat.net zone, admin included): page views / visits for `?range=24h|7d|30d` (default 7d) with a per-hour/day chart, top pages, countries (country level only, named with `Intl.DisplayNames`) and referrers (the site's own hosts and Access dropped). The numbers are sampled estimates, labelled 約 / 概数. 「よく見られた写真」 maps `/photo/<public_id>` paths (with or without the trailing slash) to media rows; other paths, old `/photo/<N>` ones included, only appear among the top pages; the edit page shows the photo's 7 d / 30 d views (`src/components/photo-views.tsx`, a `server$` over the same cached answers, from the top 1000 pages). The GraphQL helpers (`src/lib/cf-graphql.ts`) share one fetch-and-cache path (Cache API, 5 min, never throws). E2E binds a test token and `E2E_FAKE_GRAPHQL_URL` (loopback only) to `e2e/fake-graphql.mjs` (PORT+3); VRT masks the dates (`[data-date]`).
- **No publish step**: the public site reads D1 through the API Worker (`workers/api`, read-only, cached for about a minute), so a saved edit is live once that cache expires. The admin itself never writes to B2; it only presigns the browser's upload PUTs.

## Commands

```bash
cd admin
pnpm install
pnpm dev             # http://localhost:5175 (vite dev — D1 binding NOT wired here)
pnpm serve           # wrangler pages dev (D1 binding wired; use this for /media, /camera, /api)
pnpm run build.types # tsc --noEmit
pnpm test            # Vitest
pnpm run test.e2e    # Playwright E2E (e2e/*.spec.ts) — runs e2e/start-test-server.sh
pnpm run test.vrt    # Playwright VRT (e2e/vrt/*.vrt.spec.ts)
pnpm run test.vrt.update
pnpm run build       # qwik build
pnpm run deploy      # wrangler pages deploy ./dist --project-name admin-gallery-sksat-net (normally Git integration deploys instead)

# D1 lifecycle (see README.md for the full flow)
pnpm db.migrate.local
pnpm import-media && pnpm db.seed.local
```

## Test layout

- `e2e/dashboard.spec.ts` — the 容量 card's numbers from the fixture sizes; the D1 and アクセス cards and the edit page's views from the fake GraphQL API
- `e2e/access.spec.ts` — the Access JWT check is wired in (hits a second server on PORT+1 started without the bypass; expects 403)
- `e2e/media-list.spec.ts`, `e2e/media-edit.spec.ts` — `/media` flows
- `e2e/media-files.spec.ts` — the Files view (`/media/?view=files&dir=…`)
- `e2e/media-filter.spec.ts` — the filter sheet as a modal (and without JS), keyboard steps through a select, the empty state's Clear filters
- `e2e/media-visibility.spec.ts` — visibility badge/filter, edit-page change, bulk change
- `e2e/metadata.spec.ts` — a photo's metadata levels over the site defaults (`/setting/`), new private tags and the `/tag/` switch
- `e2e/camera.spec.ts` — camera list / create / edit / images and picking a camera on a photo
- `e2e/media-review.spec.ts` — going through photos in the full-screen viewer: arrows across a folder, 1/2/3 marking pending choices, 反映 (with the look at what becomes visible), undo of the batch, reload persistence and the leave guard, ignored keys, swipe and buttons on a phone
- `e2e/photo-preview.spec.ts` — the full-screen preview (thumbnail first, then the larger preset with progress; cancel on close) on `/e2e/preview/`, a page served only with the E2E server's `E2E_TEST_ROUTES=1` binding on loopback, with thumbnails Playwright answers itself
- `e2e/upload.spec.ts` — uploads into the fake bucket: progress, private rows, dedup, failure + retry, resume and delete of incomplete uploads, phone (runs last: it adds rows other specs would count; `e2e/vrt/upload.vrt.spec.ts` likewise)
- `e2e/csrf-protection.spec.ts`, `e2e/theme.spec.ts` — Origin checks on mutating requests; the theme toggle
- `e2e/mobile-*.spec.ts` — phone flows (390×844, `isMobile`, `hasTouch`): text size, tap targets, busy buttons and toasts; bulk selection and undo; the edit page's save bar, prev/next and unsaved-changes guard; the tab bar, filter sheet, scroll restore and camera pictures
- `e2e/vrt/*.vrt.spec.ts` — visual baselines (`/camera` at 1280px; `/`, `/media`, the Files view, `/media/2` and `/camera/1` at 1280px and 390px)
- `src/**/*.spec.ts` — pure-function unit tests (`db.ts`, `review-keys.ts`, `review-pending.ts`, `db-files.ts`, `folders.ts`, `validate.ts`, `format.ts`, `progress.ts`, `images.ts`, `theme.ts`, `access.ts`, `public-id.ts`, `storage.ts`, `d1-usage.ts`, `cf-graphql.ts`, `web-analytics.ts`), plus `migrations.spec.ts`, which runs the D1 migrations on an in-memory `node:sqlite`, and `neighbors.spec.ts`, which runs the edit page's prev/next query there

VRT baselines must be regenerated inside the Playwright Docker image — `admin-e2e` in [.github/workflows/ci.yaml](../.github/workflows/ci.yaml) runs the same image (`mcr.microsoft.com/playwright:v1.65.1-noble`) so baselines generated outside it drift in sub-pixel font rendering. Use the docker invocation from the root [CLAUDE.md](../CLAUDE.md) (substitute `podman` for `docker` if not in the docker group). Keep the image tag in sync with `@playwright/test` in `package.json`.

## Styling

Tailwind CSS v4 via `@tailwindcss/vite` (same setup as the root project); base styles in `src/global.css`. Use utilities only — no CSS modules or UI libraries. Shared class strings live in `src/components/ui.ts`, error/empty states use `StatePanel` (`src/components/state-panel.tsx`). Visibility has one visual language everywhere, an icon plus a label and never colour alone (`src/components/visibility-style.tsx`: public = globe, filled sky; unlisted = link, amber; private = lock, quiet zinc): `VisibilityBadge` for badges, and the same styles for the edit page's choices, the selection bar and the viewer's buttons. Phones come first: below `sm` the sections are a tab bar at the bottom (`src/components/tab-bar.tsx`; a page's own bottom bar, marked `data-bottom-bar`, replaces it, and `global.css` pads `<main>` and lifts the toast by `--bottom-ui`), the theme toggle sits in the header's menu, tap targets are at least 44px (`h-11`) and form controls use 16px text (no iOS zoom on focus; never set `maximum-scale`). Every action button is a `SubmitButton` (`src/components/submit-button.tsx`: disabled with a spinner while `action.isRunning`, the form gets `aria-busy`), and action results go to the page's `Toast` (`src/components/toast.tsx`), not inline text that can be scrolled off screen. Theme: the header toggle cycles system / light / dark, stored in `localStorage` (`admin-theme`) and mirrored on `<html data-theme>` by an inline `<head>` script before first paint (`src/lib/theme.ts`). The `dark:` variant is redefined in `global.css` to follow that attribute, and `prefers-color-scheme` when it is `system`.
